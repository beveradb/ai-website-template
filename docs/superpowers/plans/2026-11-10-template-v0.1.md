# AI Website Template v0.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build v0.1 of the public `beveradb/ai-website-template` repo. A non-technical friend can copy it, set up their accounts, build a site, and edit it safely by chatting with Claude (Code tab) or ChatGPT (Codex mode).

**Architecture:** The repo is both the template and the starting point for every friend's site. The agent instructions are template-owned files:
- `AGENTS.md`
- skills in `.agents/skills/`, symlinked into `.claude/skills/`
- `CLAUDE.md`, which contains only `@AGENTS.md`

`template-manifest.json` lists which files the template owns and which belong to the site. A small zero-dependency Node toolkit does two jobs: `scripts/check.mjs` validates repo structure, and `scripts/update-from-template.mjs` applies template upgrades. The starter site is plain HTML/CSS in `site/`. It deploys with Cloudflare Workers static assets through Workers Builds, which also builds per-branch preview URLs.

**Tech Stack:** Markdown (instructions/skills), HTML/CSS, Node ≥ 20 built-ins only (`node:test`, `node:fs`), Cloudflare Workers static assets (`wrangler.jsonc`), GitHub Actions, `gh` CLI (used by the agent on the friend's machine).

**Spec:** `docs/superpowers/specs/2026-11-10-ai-website-template-design.md`

**Out of scope here:** the andrewbeveridge.co.uk and lindsaywright.design migrations. Each gets its own plan after v0.1 ships. Their findings go into `docs/LESSONS.md` and become template fixes.

**Workflow:** Do the work in a worktree on a branch (`/start`), not on `main`.

## Global Constraints

- Every agent-facing instruction must work identically in Claude Code and Codex.
  - Canonical content goes in `AGENTS.md` and `.agents/skills/<name>/SKILL.md`.
  - `CLAUDE.md` contains `@AGENTS.md`.
  - `.claude/skills/<name>` is a relative symlink to `../../.agents/skills/<name>`.
- `SKILL.md` frontmatter uses only `name` (equal to the folder name; lowercase, hyphens) and `description` (non-empty, ≤ 1024 chars).
- `AGENTS.md` must be < 32768 bytes, the Codex cap.
- The agent never asks for, types, stores, or logs passwords, 2FA codes, recovery codes, or API tokens. Humans do signups, passwords, 2FA and payments.
- No change goes live without a preview link shown to the user and an explicit "publish" (or equivalent) from them.
- Spending money (a domain purchase) requires stating the exact price and getting an explicit yes.
- Talk to the user in plain language, with no jargon (git, branch, merge, PR, wrangler, deploy) unless they use it first. Use the plain terms instead: "draft", "preview link", "make it live", "undo".
- Human-facing docs are written at roughly a 12-year-old reading level.
- Hosting is Cloudflare **Workers** static assets with Workers Builds (not Pages). Preview builds are enabled. Use the free plan.
- Friend's accounts are their own. A helper is added only on request, as a GitHub collaborator on the site repo only.
- DNS changes for a custom domain touch only web records (apex/`www`), never MX/TXT email records.
- Runtime dependencies: none. Node built-ins only.

## Plan-level decisions (builder's calls, recorded here)

- **Local mode is the default** for friends, because of photos: they drop files into `site/images/`. Cloud mode is documented as optional.
- **The `gh` CLI is required in local mode.**
  - Install it with the official installer (macOS `.pkg` from cli.github.com, Windows `winget install GitHub.cli`).
  - Sign in with `gh auth login --web --git-protocol https`. The friend types the one-time code in their browser, so the agent never sees a token.
  - Then run `gh auth setup-git` so `git push` works.
  - The agent uses `gh` to create the repo from the template, open PRs, and merge on "publish".
- **Bootstrap without git.** The first prompt downloads `https://github.com/beveradb/ai-website-template/archive/refs/heads/main.zip` with `curl` and extracts it with `tar`. Both are built into macOS and Windows 10+.
  - After `gh` is signed in, `setup` creates `<user>/<site-name>` with `gh repo create <site-name> --private --template beveradb/ai-website-template`.
  - It then turns the current folder into a clone: `git init -b main && git remote add origin … && git fetch origin && git reset --hard origin/main`.
- **Friend repos are private.** Workers Builds supports private repos.
- **Cloudflare is connected through the dashboard, not API tokens.** In the agent browser, go to Workers & Pages → Create → Import a repository. That authorizes Cloudflare's GitHub app with no token for the agent to handle.
- **Version tracking:** `template-manifest.json` carries `version`, which replaces the spec's `.template-version`.
- **Setup progress** lives in site-owned `SETUP-PROGRESS.md`, a non-secret checklist that `setup` creates and updates so it can resume.

## Review Focus

1. **A Windows checkout turns symlinks into plain text files** containing `../../.agents/skills/x`. `check` must flag this with a fix-it message, and `update-from-template` must recreate real symlinks. (Task 1, Task 7 tests.)
2. **A template upgrade must never overwrite site-owned files**, even if upstream contains files at those paths (`SITE.md`, `site/**`, `SETUP-PROGRESS.md`, `wrangler.jsonc`). (Task 7 test.)
3. **A template upgrade that removes or renames a skill** must delete the stale skill folder and its `.claude/skills` link, not leave orphans. (Task 7 test.)
4. **A friend or agent pastes a token into a file.** `check` must fail on common secret patterns before anything is pushed. (Task 1 test.)
5. **Setup interrupted halfway** (closed laptop, CAPTCHA, lost 2FA phone) must resume from `SETUP-PROGRESS.md` without redoing finished steps. (Task 6 skill text plus the Task 9 dry run.)

### Task 7: update-from-template and add-helper

**Files:**
- Create: `scripts/update-from-template.mjs`, `tests/update.test.mjs`, `.agents/skills/update-from-template/SKILL.md`, `.agents/skills/add-helper/SKILL.md`, symlinks for both

**Interfaces:**
- Consumes: `loadManifest`, `matchesAny` (Task 1).
- Produces:
  - `applyTemplate(siteDir: string, templateDir: string) -> {from: string, to: string, added: string[], updated: string[], removed: string[]}`
    - **Add/update:** copy every file in `templateDir` whose path matches the **template's** manifest `templateOwned`, recreating symlinks as symlinks.
    - **Remove:** delete files in `siteDir` that match the **site's** current `templateOwned` but no longer exist in the template.
    - **Leave alone:** never touch anything outside the union of the two manifests' `templateOwned`.
    - Replace `.claude/skills/*` plain-file pseudo-links with real symlinks.
  - CLI: `node scripts/update-from-template.mjs <templateDir>`. Print a summary and exit 0, or exit 1 with a message if `templateDir` has no manifest.
  - **`update-from-template` skill:**
    1. Download the zip to a temp dir and extract it.
    2. Compare manifest versions. If they're equal, say "already up to date".
    3. Otherwise, on branch `change/template-<version>`, run the script and `npm test && npm run check`.
    4. Summarise the changes in plain words and include the relevant `docs/LESSONS.md` entries.
    5. Preview, then publish.
  - **`add-helper` skill:**
    - Ask for the helper's GitHub username.
    - Explain what it allows: editing this site's code only, with no access to their accounts.
    - Get a yes, then run `gh api -X PUT repos/{owner}/{repo}/collaborators/{username} -f permission=push`.
    - Tell them the helper must accept the invite. Explain removal: `gh api -X DELETE …`, or Settings → Collaborators.
    - Record it in `SITE.md` `## Notes`.
- [ ] **Step 1: Write failing tests** in `tests/update.test.mjs`, building site and template fixtures in temp dirs:
  - An updated `AGENTS.md` is copied, and `updated` includes it.
  - A new skill folder is added along with its `.claude/skills` symlink, and the link is a real symlink (`lstat().isSymbolicLink()`).
  - A template that dropped `.agents/skills/old` causes the folder and `.claude/skills/old` to be removed, listed in `removed`.
  - The template contains `SITE.md`, `site/index.html` and `wrangler.jsonc` with different content, and the site's copies are byte-identical afterwards.
  - The site has a plain-file `.claude/skills/x` (Windows case) and becomes a real symlink.
